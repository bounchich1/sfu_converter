[H2] 1 Цель
Цель работы заключалась в освоении интеграции WebSocket-клиента в веб-приложение и реализации интерфейса чата, работающего в реальном времени. В ходе работы требовалось научиться подключаться к WebSocket-серверу из браузера, обрабатывать серверные события, переключаться между комнатами, отображать актуальный список участников, показывать индикатор набора текста и уведомлять пользователя о новых событиях.

[H2] 2 Задачи
Для достижения цели были поставлены следующие задачи: создать отдельную страницу чата /chat; реализовать трехколоночный интерфейс с боковой панелью комнат, центральной областью сообщений и панелью участников; вынести WebSocket-логику в отдельный клиентский модуль; обеспечить подключение к серверу с использованием текущей cookie-сессии; реализовать автоматическое переподключение; обработать события welcome, history, message, user_joined, user_left, typing_status, online_users, room_counts, message_notify и error; добавить переключение комнат, счетчики онлайн-пользователей и непрочитанных сообщений; обеспечить адаптивное отображение интерфейса.

[H2] 3 Ход работы
Работа выполнялась на основе нового последнего коммита 2fd4b5456132c200c8484d7f7f407fde2bd765bb с сообщением lab 6 done. В предыдущей работе был реализован сервер WebSocket-чата, а в данной работе основное внимание было уделено полноценному клиентскому интерфейсу и удобному пользовательскому сценарию общения в комнатах.

[H3] 3.1 Создание страницы чата
Для отдельного интерфейса чата в src/routes/storeRoutes.js добавлен маршрут GET /chat. Он передает в шаблон список комнат через getRooms из модуля src/websocket/rooms. Страница реализована в views/pages/chat.ejs и подключена к общей навигации через views/partials/header.ejs, где появился пункт Чат с активным состоянием для пути /chat.

Разметка страницы построена как три основные области. Левая боковая панель содержит список комнат general, support, products-discussion и random, счетчик онлайн-пользователей и бейдж непрочитанных сообщений. Центральная область содержит заголовок текущей комнаты, счетчик участников, список сообщений, строку статуса typing и форму отправки. Правая панель показывает участников текущей комнаты и их состояние.

[H3] 3.2 Модуль WebSocket-клиента
Весь код низкоуровневого взаимодействия с WebSocket вынесен в public/scripts/chat/websocket.js. Модуль экспортирует в window класс ChatClient. Клиент строит адрес подключения автоматически: для обычной страницы используется ws, для HTTPS - wss, а endpoint задан как /ws/chat. Так как соединение устанавливается на тот же host, браузер автоматически передает cookie сессии ssr-store.sid, и сервер может идентифицировать авторизованного пользователя через существующий sessionMiddleware.

ChatClient реализует подписку на события через метод on, внутреннюю отправку JSON-оберток через send, методы joinRoom, leaveRoom, sendMessage и notifyTyping. Если соединение временно закрыто, сообщения помещаются в очередь _sendQueue и отправляются после восстановления соединения. При разрыве связи запускается автоматическое переподключение с задержками 1, 2, 4, 8 и 16 секунд.

[TABLE_START]
[TABLE_CAPTION] Таблица 2 - Основные методы ChatClient
| Метод | Назначение |
| connect | Создает WebSocket-подключение и назначает обработчики open, message, close и error |
| on | Регистрирует обработчик клиентского или серверного события |
| send | Отправляет JSON-сообщение с type и payload |
| joinRoom | Отправляет событие join_room и сбрасывает активный typing-таймер |
| leaveRoom | Отправляет событие leave_room для указанной комнаты |
| sendMessage | Валидирует текст, сбрасывает typing и отправляет send_message |
| notifyTyping | Отправляет typing true и через таймер typing false |
| close | Закрывает соединение и отменяет reconnect/typing-таймеры |
[TABLE_END]

[H3] 3.3 Рендеринг сообщений и защита интерфейса
Повторяемая логика формирования сообщений вынесена в public/scripts/chat/render.js. Модуль ChatRender содержит функции escapeHtml, formatTime, isSelfMessage, buildMessageElement, buildSystemMessageElement, isScrolledToBottom и scrollToBottom. Это позволило использовать одинаковый рендеринг как на отдельной странице чата, так и в компактном виджете.

При построении сообщения имя отправителя, время и текст вставляются в DOM после HTML-экранирования. Сообщения текущего пользователя определяются по userId для авторизованного пользователя или по socketId для гостевого подключения и получают отдельный CSS-класс. Автопрокрутка выполняется только если пользователь уже находился у нижней границы списка сообщений, что не мешает чтению старой истории.

[H3] 3.4 Переключение между комнатами
Логика страницы реализована в public/scripts/chat/chat-page.js. При загрузке создается объект ChatClient, регистрируются обработчики событий и запускается подключение. После события welcome клиент получает socketId, данные пользователя и список комнат. Активная комната выбирается из sessionStorage, а если сохраненного значения нет, используется general.

При выборе комнаты функция activateRoom обновляет activeRoom, сохраняет его в sessionStorage, меняет aria-pressed у кнопок, очищает область сообщений, сбрасывает typing-состояние, обнуляет бейдж непрочитанных сообщений выбранной комнаты и отправляет join_room. На серверной стороне повторный вход в новую комнату автоматически вызывает выход из предыдущей комнаты через leaveCurrentRoom, поэтому интерфейс получает актуальную историю и новый список участников.

[H3] 3.5 Отправка и получение сообщений
Форма отправки находится в нижней части центральной области. При submit скрипт проверяет наличие активной комнаты, непустой текст и открытое соединение. Затем вызывается client.sendMessage(activeRoom, text), поле ввода очищается, а собственный индикатор набора текста скрывается. В текущей реализации оптимистичное добавление сообщения не используется: сообщение появляется после подтверждающей рассылки сервера через событие message.

При получении message для активной комнаты сообщение добавляется в список через ChatRender. Если message относится к другой комнате, отдельная страница его не добавляет в текущую ленту, а использует серверное событие message_notify. Для других комнат увеличивается счетчик непрочитанных сообщений рядом с названием комнаты и показывается временное уведомление с названием комнаты, автором и кратким preview сообщения.

[H3] 3.6 Индикатор набора текста
Модуль ChatClient реализует notifyTyping: при начале ввода отправляется typing с isTyping true, затем таймер через 1500 мс без нового ввода отправляет isTyping false. На странице дополнительно отображается собственное состояние Вы печатаете..., которое скрывается по таймеру или после отправки сообщения.

При получении typing_status от других участников chat-page.js хранит состояние в Map typingUsers. Индикатор отображается в двух местах: общей строкой под областью сообщений и рядом с конкретным участником в правой панели. Если пользователь отправил сообщение или вышел из комнаты, его typing-состояние удаляется.

[H3] 3.7 Список участников и счетчики комнат
Список участников текущей комнаты обновляется по событию online_users. Для каждого пользователя отображается зеленая точка онлайн-статуса, имя, пометка гость для гостевых подключений и отдельное выделение для текущего пользователя. Заголовок центральной области и правая панель показывают количество участников активной комнаты.

Для требований по счетчикам онлайн-пользователей сервер был дополнен событием room_counts. В src/websocket/server.js добавлены buildRoomCounts и broadcastRoomCounts. Счетчики отправляются при подключении клиента, входе в комнату, выходе из комнаты и отключении. Клиент обновляет числа рядом с каждой комнатой, поэтому пользователь видит состояние не только активной комнаты, но и остальных каналов.

[H3] 3.8 Уведомления и состояние соединения
Страница показывает состояние подключения через data-chat-status. При успешном open выводится Подключено, при потере связи - сообщение о переподключении с задержкой в секундах, при ошибке - текст серверной или сетевой ошибки. Для уведомлений о новых сообщениях вне активной комнаты используется отдельный блок data-chat-notification с автоматическим скрытием через 4 секунды.

Серверная часть была расширена функцией broadcastToOthers. После успешного send_message сервер рассылает обычное событие message участникам комнаты, а клиентам в других комнатах отправляет message_notify с room, messageId, userName, preview и sentAt. Это позволило реализовать счетчики непрочитанных сообщений без загрузки чужой комнаты в текущую ленту.

[H3] 3.9 Адаптивность и интеграция с существующим виджетом
Стили страницы находятся в public/styles/chat-page.css. Для широкого экрана используется сетка 260px - основная область - 240px. На средних экранах панель участников переносится вниз, а на узких экранах все блоки становятся одноколоночными. Список комнат на мобильных экранах прокручивается горизонтально, а область сообщений ограничена по высоте.

Существующий компактный chat-widget.js также был переработан: он больше не содержит собственную низкоуровневую реализацию WebSocket и рендера, а использует общие модули ChatClient и ChatRender. Это снизило дублирование и сделало поведение виджета ближе к поведению полной страницы чата.

[H3] 3.10 Проверка реализации
Автоматические тесты были расширены новыми сценариями. Проверяется, что GET /chat возвращает страницу с тремя зонами, всеми четырьмя комнатами, формой сообщений, списком участников, скриптами websocket.js и chat-page.js, а также стилем chat-page.css. Также проверяется наличие ссылки Чат в header.

Для WebSocket-событий добавлены проверки room_counts и message_notify. Тест room_counts подтверждает отправку счетчиков при подключении, входе второго пользователя и выходе из комнаты. Тест message_notify подтверждает, что уведомление о новом сообщении получают клиенты вне комнаты сообщения, а участники той же комнаты получают только обычное событие message. Локальный запуск npm test успешно завершился: 51 test(s) passed.

[H2] 4 Вывод
В результате работы был реализован полноценный клиентский интерфейс WebSocket-чата на странице /chat. Приложение получило адаптивную трехколоночную компоновку, переключение между тематическими комнатами, историю и получение новых сообщений в реальном времени, актуальный список участников, индикаторы набора текста, счетчики пользователей по комнатам и уведомления о непрочитанных сообщениях в других комнатах.

Практическая часть показала, что для поддержки удобного WebSocket-интерфейса важно отделять транспортную логику от логики отображения. Модуль ChatClient отвечает за соединение, переподключение, очередь отправки и клиентские команды, ChatRender - за безопасное построение DOM, а chat-page.js - за состояние конкретного экрана. Такое разделение упростило повторное использование кода в компактном виджете и позволило расширить чат без дублирования низкоуровневой логики.
