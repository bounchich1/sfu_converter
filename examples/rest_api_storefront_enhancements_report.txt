[H1] Отчет о проделанной работе по заданию «Расширение SSR-магазина REST API»

[H2] 1 Цель

Целью работы было освоение принципов проектирования и реализации RESTful API на базе существующего SSR-приложения интернет-магазина, а также интеграция асинхронного взаимодействия между браузером и сервером без полной перезагрузки страницы. В рамках практики требовалось не только вернуть данные в формате JSON, но и связать новые API-эндпоинты с уже существующими страницами каталога, карточки товара, корзины, регистрации и профиля.

[H2] 2 Задачи

В ходе выполнения задания были поставлены следующие задачи.

1. Проанализировать архитектуру исходного SSR-приложения на Express и EJS и определить точки интеграции REST API.

2. Реализовать серверные JSON-эндпоинты для каталога товаров, корзины, аутентификации и оформления заказов с корректными HTTP-статусами.

3. Добавить клиентские сценарии на основе Fetch API: асинхронное добавление товара в корзину, изменение количества позиций, удаление товаров, очистку корзины и оформление заказа.

4. Реализовать дополнительные интерактивные функции: быстрый просмотр товара, проверку уникальности email при регистрации и загрузку истории заказов в профиле.

5. Обеспечить валидацию входных данных, обработку ошибок, тестовое покрытие и сохранение совместимости с SSR-режимом работы приложения.

[H2] 3 Ход работы

[H3] 3.1 Анализ исходного приложения и подготовка архитектуры

Работа выполнялась по изменениям из коммита feat: add REST API storefront enhancements. На первом этапе была проанализирована структура проекта и точка подключения новых модулей в файле src/app.js. В приложение были подключены отдельные роутеры productApiRoutes, cartApiRoutes, authApiRoutes и orderApiRoutes, смонтированные под общим префиксом /api. Такой подход позволил сохранить обычные SSR-маршруты для серверного рендера EJS-шаблонов и параллельно добавить независимый программный интерфейс для клиентских запросов.

Дополнительно была сохранена сессионная модель магазина. Пользователь и корзина продолжают храниться в express-session, а сервер передает в шаблоны текущего пользователя и счетчик товаров в корзине. Благодаря этому REST API не конфликтует с исходным SSR-поведением, а выступает как слой прогрессивного улучшения интерфейса.

[H3] 3.2 Реализация серверного REST API

На втором этапе был реализован и расширен набор JSON-эндпоинтов, покрывающий основные сущности магазина: товары, категории, корзину, аутентификацию и заказы. Эндпоинты каталога возвращают списки товаров и категорий, а также отдельный товар по идентификатору. Эндпоинты корзины работают как для авторизованного пользователя, так и для гостевой сессии, что особенно важно для сценария добавления товара с витрины без обязательного входа в систему.

Для аутентификации были реализованы маршруты регистрации, входа, выхода и получения текущего пользователя. Дополнительно добавлен GET /api/auth/check-email, который позволяет проверять занятость email еще до отправки формы регистрации. Для оформления заказов был использован отдельный сервисный слой: маршрут POST /api/orders создает заказ из текущего состояния корзины и очищает ее после успешного оформления, а GET /api/users/:id/orders возвращает историю заказов только владельцу профиля.

[TABLE_CAPTION] Таблица 1 - Реализованные REST-эндпоинты
| Метод и маршрут | Назначение | Успешный статус | Обработка ошибок |
| GET /api/products | Получение полного каталога товаров | 200 OK | Возвращает JSON-массив |
| GET /api/products/:id | Получение конкретного товара | 200 OK | 404 Not Found для неизвестного товара |

| POST /api/auth/login | Аутентификация пользователя | 200 OK | 401 Unauthorized при неверных учетных данных |
| POST /api/auth/logout | Выход из сессии | 200 OK | 401 Unauthorized для гостя |
| GET /api/auth/me | Получение текущего пользователя | 200 OK | 401 Unauthorized без активной сессии |

| PUT /api/cart/items/:productId | Изменение количества товара | 200 OK | 400 Bad Request и 404 Not Found для отсутствующей позиции |
| DELETE /api/cart/items/:productId | Удаление товара из корзины | 200 OK | 404 Not Found для отсутствующей позиции |
| DELETE /api/cart/clear | Очистка корзины | 200 OK | Возвращает пустое состояние корзины |
| POST /api/orders | Оформление заказа из текущей корзины | 201 Created | 401 Unauthorized для гостя, 400 Bad Request для пустой корзины |
| GET /api/users/:id/orders | Получение истории заказов пользователя | 200 OK | 401 Unauthorized и 403 Forbidden при нарушении доступа |
[TABLE_END]

Корректность входных данных была вынесена в файл src/utils/validators.js. В нем реализованы нормализация email, проверка обязательных полей и контроль того, что количество товара является положительным целым числом. За счет этого сервер единообразно возвращает JSON-ошибки с кодами VALIDATION_ERROR, INVALID_CREDENTIALS, NOT_FOUND, UNAUTHORIZED, FORBIDDEN, EMPTY_CART и EMAIL_IN_USE, что соответствует требованиям по обработке ошибок и статусам ответа.

[H3] 3.3 Асинхронное добавление товара и быстрый просмотр

Следующим этапом REST API был встроен в витрину магазина. В шаблонах home.ejs, products.ejs, category.ejs, product.ejs и product-card.ejs были добавлены data-атрибуты и подключен новый скрипт public/scripts/product-actions.js. Этот скрипт перехватывает отправку формы добавления товара в корзину, отправляет POST /api/cart/items, обновляет счетчик корзины в шапке страницы и показывает всплывающее уведомление об успешном действии.

В той же части интерфейса был реализован дополнительный функционал быстрого просмотра товара. Кнопка «Быстрый просмотр» вызывает GET /api/products/:id, после чего подробная информация о товаре подставляется в модальное окно quick-view-modal.ejs. Из модального окна пользователь может сразу добавить товар в корзину тем же AJAX-сценарием. Таким образом, пользователь получает интерактивное поведение, а SSR-страница при этом остается исходной точкой рендера.

[H3] 3.4 Интерактивная корзина и оформление заказа

На странице корзины шаблон views/pages/cart.ejs был переработан так, чтобы серверно отрисованные формы содержали привязку к API-маршрутам через data-api-method и data-api-url. Скрипт public/scripts/cart-page.js перехватывает отправку этих форм и выполняет асинхронные запросы к PUT /api/cart/items/:productId, DELETE /api/cart/items/:productId, DELETE /api/cart/clear и POST /api/orders.

При нажатии на кнопки + и - количество товара изменяется без перезагрузки страницы, а итоговая сумма и счетчик корзины пересчитываются на стороне клиента сразу после получения нового JSON-состояния. Перед удалением позиции реализовано подтверждение действия через window.confirm. При оформлении заказа выполняется запрос к POST /api/orders, после чего страница получает обновленное состояние корзины и выводит сообщение об успешном создании заказа. Если пользователь не авторизован, вместо кнопки оформления отображается призыв войти в систему.

[H3] 3.5 Проверка email, история заказов и доработка интерфейса

Помимо обязательной части были реализованы дополнительные улучшения, повышающие завершенность пользовательского сценария. На странице регистрации в views/pages/register.ejs добавлены элементы data-email-check и data-email-check-message, а скрипт public/scripts/register-page.js по событию blur отправляет запрос на GET /api/auth/check-email с параметром email. Если email занят, пользователь получает предупреждение еще до отправки формы.

На странице профиля в views/pages/profile.ejs и public/scripts/profile-page.js добавлена кнопка загрузки истории заказов. После нажатия выполняется GET /api/users/:id/orders, и список ранее оформленных заказов подставляется в DOM без полной перезагрузки страницы. Дополнительно в public/styles/main.css были доработаны стили для коротких страниц login, register и profile: введены классы page-shell и page-shell--centered, добавлены стили для модального окна быстрого просмотра, toast-уведомлений, элементов stepper и панели истории заказов.

Набор проверок охватывает серверные маршруты SSR, новые JSON-эндпоинты и наличие клиентских API-hook'ов в итоговой HTML-разметке. Отдельно проверялись сценарии гостевой корзины, корректность HTTP-статусов при ошибках, запрет на просмотр чужой истории заказов, наличие модального окна быстрого просмотра, клиентского скрипта проверки email и новых классов выравнивания для коротких страниц.

[H2] 4 Вывод

В результате работы существующее SSR-приложение интернет-магазина было дополнено полноценным REST API и набором клиентских AJAX-сценариев. Обязательные требования задания выполнены: реализованы эндпоинты для работы с товарами, корзиной и аутентификацией, обеспечена корректная обработка HTTP-статусов, добавлено асинхронное добавление товаров в корзину и интерактивное обновление ее содержимого без перезагрузки страницы.

Дополнительно были внедрены быстрый просмотр товара, проверка занятости email, загрузка истории заказов и визуальные улучшения интерфейса. Таким образом, работа позволила на практике освоить интеграцию RESTful API в SSR-проект, организовать обмен JSON-данными между клиентом и сервером и подтвердить работоспособность решения автоматическими тестами.
