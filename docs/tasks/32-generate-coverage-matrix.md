# Task 32: Generate Standard Coverage Matrix and Sync Gap Documentation

## Priority: Medium (closes the loop on every other task)

  must be traceable to source documents and to its current support level.

## Current state

The gap audit is maintained by hand; the registry has rule IDs and source
documents but there is no exporter that links rules to profile membership,
parser/renderer/validator status, and test coverage.

## Implementation

1. `registry/coverage.py`:
   - `build_rows() -> list[CoverageRow]` produces one row per
     `FormattingRule` with:
     - `rule_id`,
     - `profiles` (sorted list of profile names containing the rule),
     - `source_doc`, `source_section`,
     - `severity`,
     - `parser_support` (bool, derived from parser metadata — Task 02),
     - `renderer_status`, `validator_status`,
     - `test_modules` (collected by scanning `tests/` for `# rule:
       <rule_id>` markers in module docstrings).
   - `render_markdown(rows) -> str` produces the matrix.
   - `render_json(rows) -> str` for the CLI.
2. CLI:
   - `sfu-converter export-coverage --format md|json` writes the matrix.
   - `sfu-converter list-profiles --format json` now includes the same
     support data per profile (Task 02 extension).
3. Generated artefact:
   - `docs/sfu-standard-coverage-matrix.md` regenerated by the CLI;
     committed by CI when the script reports a diff (otherwise CI fails).
4. Replace the body of `docs/sfu-standard-not-implemented.md` with a
   summary plus a link to the generated matrix. Keep the human analysis
   sections that the matrix cannot capture (priority order, rationale).
5. Update `docs/pdf-vs-implementation-gap-analysis.md` to point at the
   generated matrix instead of restating per-rule statuses.
6. Add quality gates:
   - every `rule_id` resolves to a source doc that exists;
   - every `source_section` slug matches a heading inside that doc
     (markdown parsing);
   - every `IMPLEMENTED` rule has at least one `# rule: <id>` marker in
     `tests/`;
   - every appendix letter in the profile-specific rules matches Task 04's
     expanded registry.

## Tests

- Matrix generation is deterministic across two runs.
- The matrix contains every rule from `ALL_RULES` exactly once.
- The matrix shows correct profile membership for `coursework`,
  `graduation_qualification_work`, etc.
- Adding a new rule without a source-section heading fails
  `tests/test_quality_gates.py`.
